# CC-Doc-Review v0.2.0 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** 把 doc-review 整理为可公开安装的插件 CC-Doc-Review v0.2.0：改名、评论内核换成 Recogito Text Annotator（验证通过的前提下）、可配置的自动登记、预编译分发、休眠模式、适配桌面版的交互，以及发布所需文件与公开前清理。

**Architecture:** 不变——Go 本地服务（`server/`）+ 评审页前端（`server/web/static/`，无构建步骤）+ 仓库根目录即 Claude Code 插件（`hooks/register.js` + `src/` 纯函数）。

**Spec:** `docs/superpowers/specs/2026-10-11-plugin-release-design.md`（第 1–11 节）

**工作目录：** 单独的 git worktree（分支 `release/v0.2.0`）。**绝不修改** 日常开发用的插件目录（被所有会话加载）、`~/.claude/` 下任何文件、正在运行的服务。

**本计划的写法说明：** 各任务给出精确的行为、接口与验收测试，不给出完整代码——实现者为高能力模型，且第 2 个任务依赖实测得到的第三方库 API。每个任务都按 TDD：先写失败测试、再实现、再跑全量测试。

## Global Constraints

- Go 只用标准库；前端无构建步骤，第三方库放 `server/web/static/vendor/`；不使用 innerHTML 插入内容；中文字符串用全角标点。
- 引擎限制：不能把 `$` 传进从其他文件导入的函数；用到 `$` 的函数写在 `hooks/register.js`，`src/` 只放纯函数。
- 每个任务结束前运行：`cd server && go test ./... && go vet ./...`、`node --test tests/web/`、`claude plugin test .`、`claude plugin validate .`、`make build`；删除生成的 `tests/*.test.js`。
- 自测服务时用 `-dir <临时目录>` 与 `-port <4831 以上的端口>`（第 1 个任务加入 `-port`），测完按 PID 结束并删除目录。
- 名称：仓库 `sapronlee/CC-Doc-Review`；插件 / 插件市场 / 斜杠命令 `cc-doc-review`；工具前缀 `mcp__cc-doc-review__`；数据目录 `~/.claude/cc-doc-review/`；服务程序 `cc-doc-review-server`；`/api/health` 返回 `{"name":"cc-doc-review","version":...}`。

### Task 1：改名为 cc-doc-review，并加 `-port` 与版本注入

**行为**
- `.claude-plugin/plugin.json` 的 `name` 改为 `cc-doc-review`；斜杠命令 `/cc-doc-review <文件>`；工具全名变为 `mcp__cc-doc-review__review_open` / `mcp__cc-doc-review__review_resolve`（`src/rules.js` 常量与规则文字、测试、README 同步）。
- 服务：程序名 `cc-doc-review-server`（Makefile 输出 `bin/cc-doc-review-server`）；默认数据目录 `~/.claude/cc-doc-review`；`/api/health` 的 `name` 为 `cc-doc-review`；`isOurs` 认 `cc-doc-review`。
- `main.go` 增加 `-port` 参数（默认 0 = 沿用 4823～4830 自动选择；非 0 时只尝试该端口）。版本号改为 `var version = "dev"`，构建时用 `-ldflags "-X main.version=<版本>"` 注入；Makefile 的 `build` 从 `plugin.json` 读版本号注入。
- **旧数据迁移**（mod 侧，首次启动服务前执行一次）：若 `~/.claude/doc-review/` 存在且新目录下没有 `docs/`，把旧目录的 `docs/`、`outbox/` 复制到新目录；若旧目录的 `server.json` 指向的进程仍在运行且 health 名为 `doc-review`，结束该进程。迁移逻辑中的路径判断等写成 `src/` 纯函数并单测；文件操作用 `$.fs`/`$.process.run`。
- 不改 Go 模块名 `docreview`、不改仓库目录名（目录改名属于发布切换，见 Task 8 之后的人工步骤）。

**验收测试**
- Go：health 名称；`-port` 指定端口时只用该端口；`listen` 原有测试照过。
- mod：工具名、命令名为新名字；迁移纯函数（旧目录存在/不存在、新目录已有数据时不覆盖）。
- 全仓库 grep 不再出现作为插件名使用的 `doc-review`（文档中描述历史的除外）。

### Task 2：评论内核验证并替换为 Recogito Text Annotator

**行为**
- 下载 `@recogito/text-annotator@4.3.6` 的 `dist/text-annotator.umd.js`（约 65KB，自包含，全局 `RecogitoJS`）与 `dist/text-annotator.css` 到 `vendor/`，在 md 外壳页与注入的 HTML 页加载（HTML 模式由 `review.js` 动态插入 script/link，注意 `<base>` 下用绝对路径 `/static/vendor/...`）。
- 用它接管：选区捕获、高亮绘制（按状态：草稿 / 处理中 / 闪烁）、点击高亮、文档改动后重新定位、页面 DOM 变动后的重绘。保留现有右侧评论栏、编辑框、浮条（或改用库的选区事件触发我们的浮条）、Claude 风格、SSE、休眠前的全部行为。
- 评论数据格式不变（`quote`/`prefix`/`suffix` 即 W3C TextQuoteSelector）；与库之间用其 W3C 适配器或自写映射转换。
- 先做验证清单（下方），**全部通过才删除 `anchor.js`、`textmap.js`**；任一项无法满足时停止替换、保留自研实现，在报告中写明失败项与原因，并把库文件移除。

**验证清单（在临时服务上用 md 与 HTML 示例逐项实测并截图/记录）**
1. 单段选区、跨多个元素（如跨列表项、跨加粗）选区都能评论，保存的 quote 正确。
2. 三种高亮状态颜色正确，深浅色主题都可见；点击高亮定位到右侧卡片；点卡片闪烁原文。
3. 修改 md 文件后（含在被评论原文前插入内容）高亮仍在正确位置；原文被删的评论进入「原文已变动」。
4. HTML 页面：页面脚本延迟插入内容、mermaid 渲染后，新内容可选可评，已有高亮不错位。
5. 编辑中文件改动不丢输入（沿用现有推迟逻辑）；浮条/编辑框不被评论栏遮挡；窄窗口自动收起照常。
6. 控制台无报错；库的默认弹层（若有）不出现或被我们的界面替代。

### Task 3：自动登记改为 glob 模式并可配置

**行为**
- `plugin.json` 声明 `userConfig`（字段格式以插件参考文档为准，grep `userConfig`）：`includePatterns`（字符串，逗号分隔，默认 `**/specs/**/*.{md,html},**/plans/**/*.{md,html},**/docs/**/*.{md,markdown,html,htm}`）、`excludePatterns`（默认 `**/.superpowers/**,**/node_modules/**,**/vendor/**,**/dist/**,**/.git/**,**/.claude/**,**/README*,**/CHANGELOG*,**/CLAUDE.md`）、`autoRegister`（布尔，默认 true）。`register(on, options)` 读取。
- `src/` 新增纯函数 glob 匹配（支持 `**`、`*`、`?`、`{a,b}`；`**/` 可匹配零层目录），匹配相对项目根（`$.session.cwd()`）的路径；排除优先；根目录外不登记；子代理写入不登记；关闭开关时不登记。
- 替换现有按目录名判断的逻辑。

**验收测试**：glob 匹配单测（`**` 零层与多层、`{a,b}`、大小写敏感、`./` 前缀、排除优先）；配置覆盖默认值；开关关闭。

### Task 4：休眠模式

**行为**（规格第 9 节）
- 会话开始为休眠：只注册工具、命令与 Write/Edit 钩子；不启动任何定时器；`prompt.compose` 不追加评审规则（规则文字并入 `review_open` 工具说明）；`ui.render`（AbovePrompt）直接让位；`turn.complete` 直接放行。
- 唤醒条件：调用任一评审工具；`command.run` 本插件命令；自动登记命中；`session.start` 时若服务在运行（不启动服务）且 `/api/docs?session=` 有文档则唤醒。
- 唤醒后启动投递与状态轮询、一轮结束检查；保持到会话结束（`session.end`/clear 时停止定时器并复位为休眠）。

**验收测试**：休眠时零 HTTP 请求、零定时器、系统提示无评审规则；每个唤醒条件各一测；唤醒后投递正常；clear 后复位。

### Task 5：适配桌面版的交互与送达

**行为**（规格第 7、8 节）
- `review_open` 的返回文字改为：说明评审页已就绪，并指示 Claude「若有能在对话中渲染 HTML 卡片的工具（如 show_widget），画一张评审卡片：文件名、相对路径、待发送/处理中/已解决条数、按钮〔在浏览器打开〕（openLink(url)）与〔在面板打开〕（sendPrompt 让 Claude 在浏览器面板打开）；否则直接给出链接」，并附上卡片所需数据（url、文件名、各状态条数）。
- 新增工具 `review_status`：返回本会话各文档的路径、链接与各状态条数，以及待处理（sent 但未解决）评论列表（id、原文、意见）；用户说「评审进度」「看评论」时 Claude 用它。
- 送达：去掉 `$.prompt.fill` 兜底。`prompt.submit` 失败或被拒时按 5 秒、15 秒、45 秒重试；仍失败则在下一次 `prompt.submit` 钩子里把待处理评论作为 `context` 附在用户消息上，并 ack 该批次。送达成功时 toast「已收到 N 条评论，Claude 正在处理」。
- 一轮结束漏回复：不再依赖状态带按钮——检测到后自动 `prompt.submit` 一次提醒 Claude（列出评论 ID，要求调用 review_resolve），每批评论最多一次；同时 toast「还有 N 条评论没回复处理结果，已提醒 Claude」。状态带（命令行版）保留，但移除〔提醒 Claude〕按钮（改为自动）。

**验收测试**：返回文字含卡片数据；review_status 输出；重试时序与上限；转为 context 附加；toast；自动提醒每批最多一次；不再调用 prompt.fill。

### Task 6：预编译分发与版本自更新

**行为**（规格第 3 节）
- `.github/workflows/release.yml`：推送 `v*` 标签时，矩阵编译 `darwin/amd64`、`darwin/arm64`、`linux/amd64`、`linux/arm64`（`CGO_ENABLED=0`，`-ldflags "-s -w -X main.version=${tag#v}"`），产物名 `cc-doc-review-server-<os>-<arch>`，生成 `SHA256SUMS`，上传到该标签的 Release。
- mod 的 `ensureBinary`：目标路径 `~/.claude/cc-doc-review/bin/cc-doc-review-server-<插件版本>`；不存在时：`uname -sm` 判断平台 → `curl -fsSL` 下载程序与 `SHA256SUMS`（`https://github.com/sapronlee/CC-Doc-Review/releases/download/v<版本>/...`）→ `shasum -a 256` 校验 → `chmod +x`；toast「首次使用，正在下载评审服务」。下载失败且登录 shell 中有 Go（`/bin/zsh -lc` 或 `/bin/bash -lc` 执行 `command -v go`）时退回本地编译插件目录下的 `server/`；都失败给出明确错误（含平台与原因）。开发模式：插件目录下存在 `bin/cc-doc-review-server` 时优先使用它（方便本地开发）。
- 版本自更新：`/api/health` 的 version 与插件版本不一致（且不是开发模式）时，结束旧进程并启动新版本。
- 平台判定、URL 拼接、SHA256SUMS 解析写成 `src/` 纯函数并单测；下载/校验流程在 register 测试里用桩覆盖成功、校验失败、下载失败回退编译、全部失败。
