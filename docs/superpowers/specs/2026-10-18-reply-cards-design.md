# 文档回复（取代评审流程）设计

- 日期：2026-10-18
- 状态：已实现（10-19）。实施中按实测改了样子和入口，见第 15 节：输入框上方和聊天记录都改成列表，去掉右侧「文档」面板；第 5 节的卡片样式、7.4 节的小图和 10.1 节的面板已被第 15 节取代
- 版本：0.3.0（不兼容 0.2.0 的评审流程）

## 1. 为什么改

最初想要的是：Claude 写的文档，也能像聊天里那样**划一段字点「回复」**。0.2.0 做成了一套审批流程：登记 → 待评审 → 写评论 → 发送 → 处理中 → Claude 逐条报告 → 待确认 → 通过。每份文档都成了一张"等你签字的单子"。

实际用下来（截至 10-18，共登记 34 份文档）：

| 情况 | 份数 |
|---|---|
| 写了评论 | 14 |
| 没写评论，点了〔通过〕 | 9 |
| 没写评论也没通过，一直挂着 | 11 |

一多半文档其实没什么要说，工具却要求给个结论。用户认可的四个别扭点：

1. 每份都挂着等我：没意见也得点〔通过〕，不点就一直占着输入框上方那排；
2. 要两边来回跳：评论在评审页写、在评审页发，结果却在会话里看；
3. 评论要攒着再点「发送给 Claude」，不像聊天里引用完直接说；
4. 会话里杂音多：Claude 要逐条回复处理结果，没回还会被提醒。

**新的原则：照 Claude 自带的「回复」来。不说话就是没意见，没有状态、没有待办、没有结论。**

## 2. 新的用法

1. Claude 写完文档（自动登记或 `open_doc`），右侧「文档」面板里多一份，Claude 回话里附一个链接。登记不再意味着"等你确认"，只是让这份文档可以被回复。
2. 在文档页划一段字，选区上方弹出回复框，直接打字，回车（或点气泡图标）加入。
3. 这条回复变成一张卡片，出现在 Claude 输入框正上方，可以连着加好几条，每条能点 × 删掉。
4. 在输入框里写句话按回车，或点〔发送〕，卡片里的回复随这条消息一起交给 Claude。
5. Claude 照常改文档，在回话里按编号逐条说怎么处理的；文档页自动刷新，回复标记清掉，刚改过的地方标出来。

## 3. 叫法

统一叫**回复**，和 Claude 自带的一致（卡片标签写「回复」，发出的格式是 `<!-- reply -->`）。界面上不再出现「评论」「评审」「通过」「待确认」这些词。

| 位置 | 中文 | English |
|---|---|---|
| 文档页回复框的提示字 | 回复 Claude | Reply to Claude |
| 文档页顶栏 | N 条回复待发送 | N replies to send |
| 输入框上方标题行 | N 条回复 | N replies |
| 发出后的提示 | 已发给 Claude | Sent to Claude |
| 交给 Claude 的消息开头 | [文档回复] | [Doc reply] |

### 3.1 工具改名

`review_open` 改名为 **`open_doc`**（全名 `mcp__cc-doc-review__open_doc`）：不再有"评审"的意思，英文直白，各语言的用户都看得懂。插件名 `cc-doc-review` 不改，改了会影响安装和更新。

聊天记录里那一行只能显示程序名 `open_doc`：工具注册接口没有显示名字段，靠插件重画工具行来显示「打开文档」在桌面版做不到（见第 14 节）。

改名的影响：0.2.0 用户若在权限规则里写了 `review_open`，升级后要改成 `open_doc`（本机设置里没有这类规则）；README 和更新说明写明。

### 3.2 国际化

- 界面文字（回复区、文档页、文档面板、toast、交给 Claude 的消息开头）中英两套，放在一张表里，代码里不散写。
- 用哪套：读 Claude Code 的 `language` 设置（`$.config.list()`），含「中文」「Chinese」「zh」时用中文，其余用英文；读不到时用英文。
- 工具说明（给 Claude 看的 `description`）用英文写，并说明「回复会以 `[文档回复]` 或 `[Doc reply]` 开头」。
- 中文文字里的标点用全角。
- 字体已含苹方，中英都能排；按显示宽度截断（中日韩字符算 2）沿用 0.2.0 的 `displayName`。

## 4. 样式规矩

所有部件（输入框上方的回复区、文档页的回复框和标记）只用下面这些值。数值取自 CC-Gauge 用量条和 0.2.0 状态带，三者放在一起是一家人。

### 4.1 字

| 用途 | 字号 | 粗细 | 浅色 | 深色 |
|---|---|---|---|---|
| 主要文字：你写的话、标题「N 条回复」 | 13 | 500 | `#3d3d3a` | `#e6e4dd` |
| 次要文字：原文、编号、文档名 | 12 | 400 | `#8b8f97` | `#9aa0a8` |

字体：`Inter, "SF Pro Text", "PingFang SC", system-ui, sans-serif`，数字等宽（`tnum`）。回复区只用这两档字号。文档页的回复框例外，见 6.2。

### 4.2 颜色

| 用途 | 浅色 | 深色 |
|---|---|---|
| 强调色（标题行回复图标、文档里的回复标记和编号） | `#c96442` | `#e8916f` |
| 分隔线 | 黑 12% | 白 16% |
| 卡片和列表边框、行间线 | 黑 10% | 白 13% |
| 引用竖线 | 黑 20% | 白 22% |
| 卡片底色 | 黑 3% | 白 4% |

整块只有强调色这一种彩色，其余是灰色系，不和用量条的青、橙、紫抢。

### 4.3 尺寸和间距

- 行高 18（与用量条一行等高）。
- 间距按 4 的倍数：卡片内边距上下 8、左右 10；卡片之间 8；标题行与卡片 8；卡片、分隔线、用量条之间各 10。
- 卡片宽 200，圆角 8；列表圆角 8，每行高 28（字高 18，上下各 5）。
- 引用竖线粗 2，其余线粗 1（缩放时保持 1 像素）。

### 4.4 怎么画

- 卡片的外框、竖线、文字用 `Svg` 画（与用量条同法），字号、颜色、圆角都能精确控制。
- 能点的只有原生 `Button`，桌面版按钮的样子改不了，只固定位置：× 在卡片（或列表行）右上角；〔展开 / 收起〕〔清空〕〔发送〕在标题行最右边，与标题文字上下居中。卡片和列表里除了 × 没有别的按钮。

## 5. 输入框上方：回复区

### 5.1 什么时候显示

只在本会话有待发送的回复时显示；没有回复时整块不画，把位置让给下层（如用量条）。

### 5.2 标题行

```
[回复图标] N 条回复 · 显示最新 3 条                 〔展开〕〔清空〕〔发送〕
```

- 「· 显示最新 3 条」和〔展开 / 收起〕只在列表折叠 / 展开时出现。
- 〔清空〕要点两次：第一次变成「确认清空」，3 秒内再点才清空，防止误删。
- 〔发送〕：见第 7 节。

### 5.3 1 到 3 条：卡片

```
┌──────────────────────┐ ┌──────────────────────┐
│ ▎IMG_2041 → 2012…  × │ │ ▎2013 年三亚       × │
│ 日期不对，应该是 4 月 │ │ 和爷爷奶奶一起去的   │
│ 1 · 改名清单          │ │ 2 · 行程整理清单     │
└──────────────────────┘ └──────────────────────┘
```

- 第一行：竖线 + 原文（12 号灰字，单行截断）+ ×。
- 第二行：你写的话（13 号，单行截断）。
- 第三行：编号 · 文档名（去掉扩展名和日期前缀，同 0.2.0 的 `displayName`）。
- 悬停卡片时显示完整原文和完整的话（沿用 0.2.0 的悬停卡片做法）。

### 5.4 4 条以上：列表

```
┌─────────────────────────────────────────────────────────────┐
│ 5  改名清单 · IMG_3310 → 2013-02 春节   这张是元宵，不是春节  × │
│ 6  新归类方案 · 2012 年按事件分组       生日单独一组          × │
│ 7  行程整理清单 · 2015 年国庆 北京      加上去故宫那天        × │
└─────────────────────────────────────────────────────────────┘
```

- 每行：编号（宽 16）→ 文档名 · 原文（宽 220，12 号灰字，截断）→ 你写的话（占满剩余宽度，13 号）→ ×。
- 折叠时只列最新 3 条；展开后列全部。
- 展开后最多能画多少行要实测（见第 12 节）；画不下时只列最新的若干条，标题行写清总数。

### 5.5 编号

按加入顺序编号，删掉一条后其余重新编号；文档页的标记编号与之同步。

### 5.6 与其他插件共用

沿用 0.2.0 的规则：自己画完把下层内容（如用量条）接在下面，两块都有可见内容时中间画分隔线；包着下层内容的盒子不设宽度。

### 5.7 命令行版（本次只做最小可用）

完整的终端版留到下个迭代（见第 13 节）。本次只保证终端里不坏、不丢回复：

- 有待发送回复时，输入框上方显示一行：「↩ N 条回复，按回车时一起发给 Claude」，后面一个〔清空〕（两次确认）。
- 回车发送时照常附上回复（7.1 的 `prompt.submit` 钩子在终端同样生效）。
- 终端没有文档面板，入口靠 Claude 回话里的链接（10.2）。
- 不列每条回复、不提供单条删除；要删单条，在文档页的标记上删。

## 6. 文档页

### 6.1 顶栏

```
[文件图标] 改名清单.md ⌄                              [回复图标] 2 条回复待发送
```

- 左：文件名，本会话有多个文档时点它切换（沿用 0.2.0）。
- 右：本文档待发送的回复数，为 0 时不显示。
- 去掉：评审状态、〔发送给 Claude〕、〔通过〕、评论栏。文档占满整个宽度。

### 6.2 回复框

照 Claude 自带的回复框：

```
┌──────────────────────────────────────┐
│ ▎IMG_3310 → 2013-02 春节，全家在奶奶… │
│                                      │
│ 回复 Claude                     [⊕]  │
└──────────────────────────────────────┘
        IMG_3310 → 2013-02 春节，全家在奶奶家吃年夜饭。   ← 选区
```

- 浮在选区**上方**，不挡选中的字；上方放不下时放到下方。
- 宽 380，圆角 12，边框 1，底色比页面略亮一档（浅色白，深色 `#30302e`）。
- 原文：14 号灰字，左边竖线，最多两行。
- 输入：15 号，提示字「回复 Claude」，直接打字，不用先点按钮。
- 右下角气泡加号图标（lucide `message-circle-plus`）：没打字时灰色，打了字变亮。
- 回车或点图标：加入；Shift+回车：换行；Esc 或点框外：取消。没打字时回车不加入。
- 不显示操作提示文字。

### 6.3 回复标记

- 加入后，原文在文档里显示淡强调色底加下划线，后跟编号小圆点（强调色底、白字、直径 16）。
- 点编号小圆点：弹出卡片，显示「编号 · 你的回复」和内容，右上角是删除图标；再点一次、点别处或按 Esc 收起。不提供编辑，要改就删掉重写。
- 在回复区点 × 删掉，标记同步消失（文档页随服务端数据刷新）。
- 发给 Claude 之后标记全部清掉，文档恢复干净，不留历史印记。
- Claude 改了文档、文档页刷新后：按原文和上下文重新定位标记（沿用 0.2.0 的 `anchor.js`）；找不到原文时不画标记，回复区的卡片照旧保留。

### 6.4 标出 Claude 改了哪里

- 文档内容变了、页面自动刷新时，按段落（标题、段落、列表项、表格行、代码块）比较新旧内容，新增或改过的段落左侧画一道强调色竖线，底色淡强调色。
- 顶栏右侧显示「改了 N 处」和上下两个小箭头，点箭头在改动之间跳；有待发送回复时，两项并排。
- 刷新后自动滚到第一处改动；你正在写回复（回复框开着）或刚滚动过（3 秒内）时不自动滚，免得打断。
- 标注保留到下一次内容变化，或你点顶栏的「改了 N 处」旁的 ×；删除的段落不显示。
- 只比较本页打开期间的变化：页面打开前的改动不标。

### 6.5 能回复的内容

- 能划：正文文字、表格里的字、代码块里的字、标题。
- 本次不支持：Mermaid 流程图、图片、HTML 页面里的画布或嵌入内容。划到这些区域时不弹回复框。以后可以加「悬停出现回复按钮，针对整张图回复」。

## 7. 发送

### 7.1 两种发法

| 发法 | 做法 |
|---|---|
| 在输入框写句话按回车 | `prompt.submit` 钩子改写这条消息的 `text`：你写的话在前，回复块（7.2）接在后面 |
| 点〔发送〕 | `$.prompt.submit({ text, asUser: true })`，`text` 同样是你的话（默认「请看这几条回复」）加回复块（插件自己发的消息不经过自己的 `prompt.submit` 钩子，测试已确认） |

两种发法都把回复**写进消息正文**，不用 `context`：`context` 在聊天记录里看不到，你回头翻记录不知道当时回复了什么；写进正文后，聊天记录、Claude 收到的内容都一样，插件再按 7.4 画成卡片。插件被停用时，正文仍是可读的文字。

只挂在用户自己发的消息上（`origin.kind` 为 `composer` / `bridge` / `sdk`），插件或系统注入的消息不带。

### 7.2 交给 Claude 的格式

照 Claude 自带的回复格式，前面加一行说明是哪份文档：

```
[文档回复] 请按编号逐条答复。
改名清单.md（/Users/…/改名清单.md）
<!-- reply 1 -->
> IMG_2041 → 2012-05 春游

日期不对，应该是 4 月

<!-- reply 2 -->
> IMG_3310 → 2013-02 春节

这张是元宵，不是春节
```

回复块放在你写的话后面，以 `[文档回复]` 一行开头（英文为 `[Doc reply] Please answer each by number.`）。多份文档按文档分组，每组一行文件名和路径；编号全局连续，与卡片一致。

### 7.3 反馈

- 按下〔发送〕：按钮立刻变「发送中…」，不能重复点。
- 发出后：回复区收起，文档页标记清掉，toast「已发给 Claude」。
- 失败：回复全部保留，toast 写明原因，可以再发。
- 回车发送时没有按钮可变，发出后同样收起回复区并清标记，不弹 toast（消息本身已出现在会话里）。

### 7.4 发出的消息在聊天记录里的样子

插件在 `ui.render` 的 `UserMessage` 上认出正文里的回复块，把这条消息画成：

```
                         ┌──────────────────────────────┐
                         │ ┌──────────────────────────┐ │
                         │ │ ▎IMG_2041 → 2012-05 春游  │ │
                         │ │ 日期不对，应该是 4 月      │ │
                         │ │ 1 · 改名清单               │ │
                         │ └──────────────────────────┘ │
                         │ ┌──────────────────────────┐ │
                         │ │ ▎2013 年三亚              │ │
                         │ │ 和爷爷奶奶一起去的        │ │
                         │ │ 2 · 行程整理清单           │ │
                         │ └──────────────────────────┘ │
                         │ 这两处改一下                  │
                         └──────────────────────────────┘
```

- 回复卡片在上，你写的话在下；卡片竖着排，样子和回复区的卡片一样（第 4 节），只是没有 ×。
- 4 条以上用列表（同 5.4），不折叠，全部列出。
- 回复块那几行原始文字（`[文档回复]`、`<!-- reply -->`、`>`）不显示。
- 点〔发送〕、没自己写话时，不显示默认的「请看这几条回复」，只显示卡片。
- 认不出格式（比如手动改过）时照原样显示文字，不报错。
- `isExpanded` 为 false 的折叠视图里画成一行「N 条回复 · 你写的话的开头」。

## 8. 去掉的东西

| 去掉 | 说明 |
|---|---|
| 评审状态（待评审、未发送、处理中、待确认、已通过） | 服务端不再计算 `state`，状态带不再按状态列文档 |
| 〔通过〕和「已通过」消息 | 删除 `/api/approve` |
| 〔发送给 Claude〕、发送批次、outbox 送达与重试 | 发送改由插件在 `prompt.submit` 里完成，删除 `/api/send`、`/api/outbox`、`/api/outbox/ack` |
| `review_resolve`、`review_status` 两个工具 | Claude 改完照常回话即可 |
| 「还有 N 条评论没回复处理结果」提醒 | 一并删除 |
| 状态带里的文档列表 | 没有回复时不显示任何东西 |
| 评审页右侧评论栏 | 见 6.1 |

## 9. 服务端

- 回复沿用现有的 `Comment` 记录：`draft` 即待发送的回复。字段 `quote`、`prefix`、`suffix`、`body` 不变。
- 新接口 `GET /api/replies?session=…`：本会话所有文档里待发送的回复，按加入时间排序，带文档 ID 和路径；插件每秒取一次画回复区。
- 新接口 `POST /api/replies/sent {ids}`：插件发出后调用，把这些回复标为 `sent`，从此不再显示；数据保留在文件里，不做界面。
- `DELETE /api/comments` 沿用，供 × 和〔清空〕调用（〔清空〕逐条删，或新增批量参数）。
- `GET /api/doc` 只返回待发送的回复，供文档页画标记。
- 删除第 8 节列出的接口和状态计算代码，以及对应的测试。

## 10. 文档入口与 Claude 的工具

### 10.1 右侧「文档」面板

插件自己的面板（`$.ui.open` + `ui.render` 的 `Pane`），桌面版放在窗口最右边单独一列（10-18 实测：标题栏带放大、关闭按钮），不在桌面版自带的侧边栏里。

```
文档                              ⤢ ✕
本会话 · 2 份
┌────────────────────────────────┐
│ 改名清单                  [新] │
│ 照片整理 · 更新于刚刚          │
│ 2 条回复待发送                 │
│ 〔在面板打开〕                 │
└────────────────────────────────┘
┌────────────────────────────────┐
│ 新归类方案                     │
│ 照片整理 · 20 分钟前           │
│ 〔在面板打开〕                 │
└────────────────────────────────┘
```

- 列出本会话登记过的所有文档（自动登记和 `open_doc` 都算），最近更新的在上。

## 13. 不在本次范围

- 输入框**里面**的卡片。原因：

  - 测试插件实测（10-18，桌面版）：`$.prompt.fill` 写进的文字能显示，但上色**没有显示**。说明桌面版的输入框是应用自己画的，只同步文字，不认插件的装饰。

## 15. 实施中的改动与实测结论（10-19，桌面版内置 Claude Code 2.1.299）

### 15.1 经过

按第 5 节做出输入框上方的回复区后，在开发版（热重载）会话里实测：Claude 空闲时输入框上方经常不显示。中途改过一版「回复直接插进输入框」（`$.prompt.fill`），能用但只能是纯文字，你觉得不好看。后来用最小的探针插件、以正式安装的方式（项目本地范围装入测试项目，不热重载）实测：Claude 空闲时，读插件状态的输入框上方内容和自刷新的 `Client` 部件都能每秒刷新。所以之前的问题出在开发版热重载，不在插件。最后回到输入框上方，并把样子统一成列表。

### 15.2 现在的做法

- **输入框上方的回复列表**（表格样式，10-19 你看过同一份代码生成的预览后确认）：圆角外框；第一行（表头）「↩ N 条回复 · 文档名」，右边〔展开其余 N 条〕│〔清空〕〔发送〕（展开后是〔收起〕）；下面一条回复一行（行高 28 像素），行与行之间通栏横线（单独一条，贯穿外框，不被行尾的 × 挡住）、栏与栏之间不画线；每行：橙色编号圆点、灰色竖线加暗色原文（栏宽约 206 像素，太长截短）、亮色回复（栏宽约 430 像素）。鼠标停在某行上底色变浅、行尾出现 ×。最多先列最新 3 条；可用高度不够时更少，展开后也只列放得下的条数。
  - 「画的就是做的」：每一行（圆点、竖线、原文、回复）和横线都由 `src/bandart.js` 画成图，预览页和插件用同一组函数，字体用桌面版的系统字体。表头（↩、N 条回复、· 文档名）用桌面版的文字，和右边〔展开其余 N 条〕〔清空〕〔发送〕同一种字体、同一条基线；按钮文字不带箭头符号（箭头符号和文字对不齐）。表头左边和下面每行的编号圆点对齐（图里左边距 0）。图画得很宽（2000 像素）并用 `preserveAspectRatio="xMinYMid slice"`：桌面版把它限制在行宽内时只裁不缩，所以横线总是通栏、文字不会被缩小。外框也是插件画的（上沿、下沿、左右边框、四个圆角都是图）：桌面版自带的边框在框内多出一圈量不准的内边距、上下多出半行空白，换成自己画后，横线两头接到边框，编号圆点、标题的 ↩ 离左边框 8 像素，和〔发送〕、× 离右边框的距离（桌面版按钮自带的内边距）差不多，上下沿只留圆角的 6 像素；表头和最后一行各矮 6 像素，加上上下沿正好一行高，每行看起来一样高；列表的行与行之间明确不留空（桌面版默认会空约 3 像素）；〔发送〕右边再空 4 像素，和左边的留白对称。按钮（〔展开〕〔清空〕〔发送〕×）是桌面版自己的，图里画了也点不了。
  - 高度：这一块最多 `maxRows` 行；回复区先算下层内容（本插件之后的插件画的）占几行，再给外层插件（如用量带）留 3 行，外框和表头占 3 行，剩下几行就最多列几条，不再把用量带挤进滚动区。
  - 终端没有图：画成文字（编号、│ 原文、回复）。
- **发送**：同第 7.1、7.2 节，回车时把回复块写进消息正文，或点〔发送〕。
- **聊天记录**：认出回复块的消息画成和回复区一样的列表（回复完整折行，没有 × 和按钮），你写的话放在下面。
- **去掉右侧「文档」面板**：〔在面板打开〕在自动模式下被拒，面板意义不大；`/cc-doc-review` 不带参数改为在聊天里列出本会话的文档和链接。
- **开发测试方式**：改完代码后以正式安装的方式装进测试项目（项目本地范围），新开会话看效果，不再用热重载的开发版验收界面。

### 15.3 实测结论（补充第 14 节）

| 插件能做的 | 结果 |
|---|---|
| `AbovePrompt` 在 Claude 空闲时重画 | 正式安装时能：读插件状态的内容每次写入都重画，`Client` 部件自己每秒刷新也正常（探针实测）。开发版热重载的会话里空闲期一次都不画，是热重载造成的 |
| `session.start` 的 `e.surface` | 桌面版是 `null`。要判断是否在桌面版，得在用到时调 `$.session.surfaces()` |
| `$.prompt.fill` 在空闲时写输入框 | 能 |
| `$.prompt.fill` 和 `prompt.edit` 的 `decorations`（上色、变暗） | 桌面版不显示，命令行版未测 |
| `$.prompt.read` | 读到的末尾空行和输入框里实际的对不上，往后接文字会多出空行，所以改为整框替换 |
| `prompt.edit` | 桌面版输入框里的删改会触发，能据此实时同步删除 |
| `prompt.submit` 加 `context` | Claude 能收到，不显示在聊天记录里 |
| `UserMessage` 用 `Svg` 画卡片 | 能（只在深色主题下看过） |
