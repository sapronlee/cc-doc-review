# 评审状态与「通过」设计

- 日期：2026-10-12
- 状态：已实现，待评审

## 1. 目的

评审是为了让 Claude 写的文档**经过你的确认再定稿**：你看 → 提意见 → Claude 改 → 你确认。

状态带只回答一个问题：**哪些文档在等谁做什么**。轮到你的要提醒你，轮到 Claude 的让你看到进度，谁都不用做的不显示。

## 2. 状态

| 状态 | 含义 | 轮到谁 | 图标（lucide） | 颜色 |
|---|---|---|---|---|
| **待评审** | Claude 写完或改完，你还没给结论 | 你 | `file-search` | 粉 |
| **未发送** | 你写了评论，还没点「发送给 Claude」 | 你 | `file-pen` | 黄 |
| **待确认** | Claude 处理完了，等你核对改得对不对 | 你 | `file-check` | 绿 |
| **处理中** | 评论已发给 Claude，还没处理完 | Claude | `hourglass` | 灰 |
| 已通过 | 你点了〔通过〕，这篇定稿 | — | — | 不显示 |

**图标形状和颜色一起区分状态**：「评审」二字已用陶土色，4 种状态各用一种颜色，按常见语义：粉是新的、等你看（不用蓝：状态带里的文件名链接是桌面版固定的蓝色），黄是你还有事没做完，绿是改完了等你确认，灰是在等 Claude。每种颜色有浅色、深色两套；评审页顶栏的状态用同一套颜色。

一篇文档同一时间只有一个状态，按下面的顺序判断，先命中的为准：

1. 有未发送的评论 → **未发送**
2. 有处理中的评论 → **处理中**
3. 点过〔通过〕，且之后没有新的登记、也没有新解决的评论 → **已通过**（不显示）
4. 上次〔通过〕之后有评论被解决 → **待确认**
5. 其余（新登记，或通过后又被重新登记）→ **待评审**

状态带只显示前四种，且只显示**最近 24 小时内有变化**的文档（登记、评论新建 / 发送 / 解决、通过）；超过 24 小时没动静的自动退出状态带，文档和评论都保留，重新登记即可再出现。

### 流程

```
待评审 ──写评论──▶ 未发送 ──发送给 Claude──▶ 处理中 ──Claude 全部处理完──▶ 待确认
  │                                                                       │
  └──没意见，点〔通过〕──▶ 已通过 ◀──────核对没问题，点〔通过〕─────────────┘
                              │      （还有意见就继续写评论，进入下一轮）
                              └──Claude 又改了这篇并重新登记──▶ 待评审
```

## 3. 评审页顶栏

评审页是一个完整的小页面：顶部一条固定的顶栏，右侧是评论栏，中间是文档。三者共用一种底色，只用细线分区，文档本身不加框。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 💬 评审 / 接口设计.md ⌄  ✎ 未发送        还有 1 条评论没发送 〔发送给 Claude（1）〕〔通过〕 │
├───────────────────────────────────────────────────┬──────────────────────┤
│                                                   │ 评论  1 未发送        │
│   文档正文（Markdown 居中限宽；HTML 保持原样）       │ ┌ 草稿 ───────────┐  │
│                                                   │ │ …               │  │
└───────────────────────────────────────────────────┴──────────────────────┘
```

- 顶栏左侧：陶土色的评审图标和「评审」、文件名（本会话有多个文档时点它切换）、当前状态（彩色图标和名称）。
- 评论栏标题：「评论」和各类条数，只列不为 0 的（如「1 未发送 · 2 已解决」）。
- 右侧两个按钮，可用状态如下：

| 状态 | 〔发送给 Claude〕 | 〔通过〕 |
|---|---|---|
| 待评审 | 不可用 | **可用** |
| 未发送 | **可用**，显示条数「发送给 Claude（2）」 | 不可用，提示「还有 2 条评论没发送」 |
| 处理中 | 不可用 | 不可用，提示「Claude 还在处理评论」 |
| 待确认 | 不可用 | **可用** |
| 已通过 | 不可用 | 不可用，按钮文字变为「已通过」 |

- 〔发送给 Claude〕和〔通过〕都在顶栏右侧，同一时间最多一个实心按钮：未发送时是〔发送给 Claude〕，待评审、待确认时是绿色的〔通过〕；其余是描边按钮。评论栏只负责列出评论。
- 点〔通过〕：文档进入「已通过」，并给 Claude 发一条消息「[文档评审] xx.md 已通过评审」，Claude 据此知道这篇定稿，可以继续下一步。
- 窄屏时顶栏照常显示，原因文字和状态名称隐藏，只留图标。
- 外框明暗跟着文档走：Markdown 跟随系统；HTML 看页面实际的背景色（body、html 的背景，没设就看浏览器画布），外框底色和页面一致。没写任何样式的 HTML 补上默认的边距和行高，写了样式的不动。

## 4. 服务端

- 文档记录：已有 `openedAt`（最近一次登记时间）；新增 `approvedAt`（最近一次通过时间）。
- 新接口 `POST /api/approve {doc}`：只有「待评审」「待确认」时可以通过，否则返回错误说明原因。成功时记录 `approvedAt`，并往文档所属会话的 outbox 写一条「通过」消息。消息复用评论批次的格式，加一个 `kind: "approve"`、不带评论，送达、重试、确认都沿用现有逻辑。
- `GET /api/doc` 的返回也带上 `state`，评审页的顶栏据此决定按钮能不能点。
- 文档概况（`GET /api/docs`）新增 `state` 字段，取值 `review` / `draft` / `processing` / `confirm` / `approved`，按第 2 节的规则计算；同时给出 `changedAt`（最近一次变化时间），插件据此判断 24 小时。
- 通过后再被登记（`Open`）：`openedAt` 晚于 `approvedAt`，状态回到「待评审」。

## 5. 状态带（插件）

- 显示状态为 `review` / `draft` / `processing` / `confirm`、且 24 小时内有变化的文档；排序：未发送、待确认、待评审、处理中（先排轮到你的）。
- 每个文档和下面的用量一样平铺不加框：lucide 状态图标加文件名，图标按状态换形状、换颜色；文件名是 Markdown 链接，点了在系统浏览器打开评审页（桌面版的链接一律走外部浏览器；插件主动调内置浏览器在自动权限模式下会被拦下，所以不再尝试）。要在浏览器面板看，用对话里评审卡片的〔在面板打开〕。
- 「评审」悬停卡片：标题「文档评审」，下面是图例，每种状态一行「图标 待评审　2 篇」，只列不为 0 的。
- 文件悬停卡片只留：全名、「目录 · N 分钟前更新」。条数和说明文字都去掉。
- 「已通过」消息和评论批次走同一条送达通道（发送失败重试、附到下一条消息）。
- 命令行版：每个文档一行，状态写成文字标签（「待评审」「未发送」「处理中」「待确认」）。
- 旧版服务端没有 `state` 时，按原来的规则（有未解决评论才显示）处理。
