# 插件发布方案

- 日期：2026-10-11
- 状态：待评审

## 1. 目标

把评审页、本地服务和 mod 整理成一个可以公开安装的 Claude Code 插件，发布到个人 GitHub。别人用两条命令即可安装：

```
/plugin marketplace add sapronlee/claude-plugins
/plugin install cc-doc-review@sapronlee
```

`cc-doc-review@sapronlee` 的格式是「插件名@插件市场名」：`@` 前是要装的插件，`@` 后是第一条命令添加的插件市场。

**系列化**：作者的插件统一放在一个总市场里，以后新插件只要在总市场里加一条，用户添加一次市场就能安装全部插件。

| 层级 | 名字 |
|---|---|
| 总市场仓库 | `sapronlee/claude-plugins`，只放 `.claude-plugin/marketplace.json` 和说明 |
| 插件市场名 | `sapronlee` |
| 插件仓库 | `CC-<名字>`，如 `sapronlee/CC-Doc-Review`；总市场的条目用 `{"source": "github", "repo": "sapronlee/CC-Doc-Review"}` 指向它 |
| 插件名 | `cc-<名字>`，如 `cc-doc-review`。保留 `cc-` 前缀：插件名同时是工具名前缀、斜杠命令和数据目录名，通用名容易和别人的同名插件冲突 |

插件仓库自身不再带 `marketplace.json`，避免两个安装入口。

**命名**（沿用作者 CC- 前缀的命名规则）：

| 用途 | 名字 |
|---|---|
| GitHub 仓库 | `sapronlee/CC-Doc-Review` |
| 插件 | `cc-doc-review` |
| 插件市场 | `sapronlee`（总市场 `sapronlee/claude-plugins`） |
| 斜杠命令 | `/cc-doc-review <文件>` |
| 工具 | `mcp__cc-doc-review__review_open`、`mcp__cc-doc-review__review_resolve` |
| 数据目录 | `~/.claude/cc-doc-review/` |
| 服务程序 | `cc-doc-review-server` |

本地仓库目录也从 `doc-review` 改名为 `CC-Doc-Review`。旧数据目录 `~/.claude/doc-review/` 里的评论在首次启动新版本时迁移到新目录。

## 2. 自动登记：目录加文件匹配模式

改为 glob 模式，匹配**相对项目根目录**的路径，语法与 `.gitignore` 相近：`**` 匹配任意层目录，`*` 匹配文件名中的任意字符，`?` 匹配单个字符，`{a,b}` 匹配其中之一。

| 配置项 | 默认值 |
|---|---|
| 包含模式 | `**/specs/**/*.{md,html}`、`**/plans/**/*.{md,html}`、`**/docs/**/*.{md,markdown,html,htm}` |
| 排除模式 | `**/.superpowers/**`、`**/node_modules/**`、`**/vendor/**`、`**/dist/**`、`**/.git/**`、`**/.claude/**`、`**/README*`、`**/CHANGELOG*`、`**/CLAUDE.md` |
| 自动登记开关 | 开 |

- 同时命中包含与排除时以排除为准。
- 项目根目录之外的文件、子代理写的文件始终不自动登记。
- 例：只想评审某个目录下的方案，可把包含模式改成 `design/**/*.md`。

**如何配置**（三项都是插件选项，多个模式用逗号分隔）：

1. 在命令行版 Claude Code 里运行 `/plugin`，进入已安装的插件，选中 `cc-doc-review`，选「Configure options」逐项填写。
2. 也可以直接编辑 `~/.claude/settings.json`，选项保存在 `pluginConfigs` 下，键是「插件名@插件市场名」：

```json
{
  "pluginConfigs": {
    "cc-doc-review@sapronlee": {
      "options": {
        "includePatterns": "design/**/*.md,**/specs/**/*.md",
        "excludePatterns": "**/drafts/**",
        "autoRegister": true
      }
    }
  }
}
```

没填的项用上表的默认值。修改后新开的会话生效。

## 3. 服务程序：预编译分发，使用者不需要 Go

不再要求使用者安装 Go，改为预编译二进制随版本发布：

- **发布**：给仓库打版本标签（如 `v0.2.0`）时，GitHub Actions 自动编译 macOS（Apple 芯片、Intel）和 Linux（x86_64、arm64）四个平台的程序，连同 SHA-256 校验文件一起上传到该版本的 GitHub Release。
- **安装后第一次使用**：插件识别当前系统和芯片，用 `curl` 下载对应程序，校验 SHA-256 后保存到 `~/.claude/cc-doc-review/bin/cc-doc-review-server-<版本>`，提示「首次使用，正在下载评审服务」。
- **升级内核**：发新版本时插件版本号与程序版本号一致；插件更新后发现本地没有新版本程序就自动下载，后台运行的旧版本服务自动重启为新版本。升级内核就是「改代码 → 打标签 → 用户 `/plugin update`」。
- **兜底**：下载失败且本机有 Go 时，退回本地编译（方便开发者和不支持的平台）；两者都不行时给出明确的错误提示。
- 暂不支持 Windows。

## 4. 评论内核：是否改用现成的开源库

评审页里「选中文字 → 记录原文位置 → 高亮 → 文档改动后重新定位」这部分，目前是自己写的（`anchor.js`、`textmap.js`）。开源社区有成熟的现成实现：[Recogito Text Annotator](https://github.com/recogito/text-annotator-js)。

| | 现在的自研实现 | 改用 Recogito Text Annotator |
|---|---|---|
| 许可证 | 自有 | BSD-3-Clause |
| 数据格式 | 自定义 JSON | W3C Web Annotation 标准（TextQuoteSelector / TextPositionSelector） |
| 选区、高亮、跨元素选择、撤销重做 | 自己维护，已覆盖本项目需要的场景 | 库内置，社区维护，升级换版本即可 |
| 集成成本 | 无 | 需要重写评审页的选区与高亮部分，并把现有评论数据迁移为 W3C 格式 |
| 风险 | 复杂页面下的边界情况要自己踩 | 它自带的交互（选区弹层、高亮样式）要和现有右侧评论栏、Claude 风格对齐 |

验证结论（2026-10-11）：**不采用，继续使用自研实现。** 在 Chrome 中按 6 项清单实测，功能均可通过，但接入后发现：

1. 库只按字符偏移还原标注位置，不按「原文 + 前后文」重新定位；文档修改后的重新定位这一最难的部分仍需自研 `anchor.js`，库只接管了本已完善的选区、高亮绘制与点击命中。
2. 4.3.6 的 UMD 包在浏览器中调用即报 `process is not defined`，需要临时补丁才能运行。
3. 库对容器内所有非链接点击调用 `preventDefault`，被评审 HTML 页面的复选框、折叠块、表单按钮失效，只能依赖其内部实现跳过该监听，升级即可能失效。
4. 库会给被评审页面的 body 加 `tabindex`、绑定全局热键、清空页面自身的 CSS 高亮，自带样式表还会改动页面全局样式。

换用它既不能减少维护难点，又引入补丁、对内部实现的依赖和对被评审页面的侵入，与「不改动被评审页面」的原则相悖。接入代码已撤销。

## 5. 插件发布所需文件

- 总市场仓库 `sapronlee/claude-plugins` 的 `.claude-plugin/marketplace.json`：列出本插件，指向本仓库。
- `plugin.json`：版本号 0.2.0，补充主页、仓库地址、许可证字段。
- `.github/workflows/release.yml`：打标签时编译四个平台的程序并上传到 Release。
- `LICENSE`：MIT。
- `THIRD_PARTY_NOTICES.md`：marked（MIT）、DOMPurify（Apache-2.0 / MPL-2.0）、highlight.js（BSD-3-Clause）、mermaid（MIT）、lucide 图标（ISC）。
- `README.md`：**英文**，写清安装、使用、配置、安全说明和系统要求（macOS / Linux）。
- `README.zh-CN.md`：中文版 README，内容与英文版一致；两份 README 顶部互相链接。

## 6. 公开前的清理

当前仓库中有不适合公开的内容：

- 设计文档、计划里的本机绝对路径（用户目录下的路径）。
- 对作者其他私有项目的引用。
- 示例和文档里与工作相关的业务字眼。

处理方式：

1. 逐个文件排查，清理或改写上述内容，排查结果列给作者确认。
2. 公开仓库使用一份全新的提交历史（只有一个初始提交），本地仓库保留完整历史不动。

## 7. 桌面版的交互方式

桌面版有三处可以放评审信息：

| 位置 | 内容 |
|---|---|
| **输入框上方的状态带** | 桌面版只占一行，靠左排：陶土色评论图标和「评审」，后面是文件药丸，每个为「lucide 线条文件图标（HTML 为地球）+ 原生按钮」，按钮上是去掉扩展名和日期前缀、过长截断的文件名，点了直接打开评审页（原生按钮只能放一段文字，所以图标紧贴在按钮左边）。放几个按状态带宽度估算，其余收成「+N」，悬停时列出其余文件的药丸。悬停卡片参照 shadcn HoverCard：「评审」卡片是标题、文档数和「N 条 Claude 处理中　M 条未发送」；文件卡片是全名、「目录 · N 分钟前更新」和这篇的条数（为 0 的不列）。不放按钮，也不重复说明。一轮结束仍有评论没回复时，标题换成提醒，带〔×〕收起。24 小时内登记、还没有任何评论的文档算「待评审」，药丸用浅色排在后面，作为开始评审的入口（服务端在文档概况里提供 resolved 和 openedAt）；有过评论的不算。既没有未解决的评论、也没有待评审文档时不显示。与同一位置的其他插件（如 CC-Gauge）上下排列，两块都有可见内容时中间画分隔线（上下留白与外框内边距一致），只有一块时不画；包着其他插件内容的盒子不设宽度（引擎节点不能放在设了 width 的 Box 下）。命令行版为标题行加每个文档一行文字，带〔复制链接〕〔打开〕，超过 3 个可展开。 |
| **聊天里的评审卡片** | 打开评审页时，Claude 画一张卡片：文件名、待发送 / 处理中 / 已解决条数，按钮〔在浏览器打开〕和〔在面板打开〕。能画卡片时用卡片，否则贴链接。用户说「评审进度」时画汇总卡片。 |
| **弹出提示** | 评论送达时提示「已收到 N 条评论」；自动提醒 Claude 漏回复的评论时也弹出提示。 |

**和其他插件共用状态带**：输入框上方这块位置，多个插件按加载顺序一层套一层，先加载的在外层。本插件画完自己的那行后，会把内层插件（比如用量带）的内容接在下面，不独占这块位置。但外层插件如果画完不让位，本插件的状态带就显示不出来。

已知情况（2026-10-11 实测）：用户的 `CLAUDE_CODE_PLUGIN_DIRS` 里用量带排在前面，它在外层且不让位，状态带被挡住，因此早先误以为桌面版不显示状态带。解决办法是把本插件排到前面，安装版插件可以在用户设置里用 `prependPlugins` 指定排在外层。

## 8. 评论送达：不再使用输入框兜底

- 插件把评论作为消息发进会话（目的是唤醒 Claude）；发送失败时**稍后重试**，不再把评论填进用户输入框。
- 重试仍未成功时，把待处理评论**附在用户的下一条消息上**一起交给 Claude。
- 新增工具 `review_status`：Claude 随时可以取本会话各文档的进度与待处理的评论（用户说「看评论」「评审进度」时也用它）。

## 9. 休眠模式

插件全局安装，但只在真正用到评审的会话里工作。每个会话开始时处于休眠：

| 功能 | 休眠时 | 唤醒后 |
|---|---|---|
| 评审工具、斜杠命令 | 在 | 在 |
| 写文件时的自动登记判断 | 在（只做路径匹配，不联网、不提示；命中即唤醒） | 在 |
| 系统提示里的评审规则 | 不加；规则写进评审工具自己的说明 | 不加 |
| 每秒查新评论、拉进度 | 不运行 | 运行 |
| 一轮结束检查漏回复 | 不运行 | 运行 |

唤醒条件（任一满足即唤醒，并保持到会话结束）：Claude 调用任一评审工具；用户使用斜杠命令；自动登记命中；本会话登记过文档且服务在运行（会话开始时查一次；服务不在时读本机数据目录里的文档文件，本会话登记过文档就直接启动服务并唤醒，没有则之后每轮开始时再查；实测发现退出 Claude 会把服务一起关掉，不这样做的话重启后状态带要等有人调用评审工具才出现）。

评论只会发往打开评审页的会话，而该会话在打开时已唤醒，因此不会漏送。

注：开发期间其他会话里出现的「reloaded」提示来自「从开发目录加载插件」，与休眠模式无关；改为 `/plugin install` 安装版后消失。

## 10. 发布与切换

1. 开发分支合并进 main。
2. **推送前**和作者确认 GitHub 用户名与仓库名，再创建插件仓库和总市场仓库、推送，并给插件仓库打第一个版本标签。
3. 用 `/plugin install` 正式安装后，删除 `~/.claude/settings.json` 中 `CLAUDE_CODE_PLUGIN_DIRS` 里本仓库的路径，避免同一插件被加载两次（这一步同样先确认）。

## 11. 不在本次范围

- Windows 支持。
- 插件的自动更新提醒。
