# CC-Doc-Review

[English](README.md) | 简体中文

一个 Claude Code 插件，让你直接在 Claude 写的文档上回复。在浏览器里打开 Markdown 或 HTML 文件，选中一段文字写回复，和在聊天里引用一条消息一样。回复会随你的下一条消息一起交给 Claude。对某份文档没什么要说，什么都不用做：没有状态，没有审批，也没有待办。全部在本机运行。

## 安装

```
/plugin marketplace add sapronlee/claude-plugins
/plugin install cc-doc-review@sapronlee
```

第一条命令添加的是 [SummErOK 的插件市场](https://github.com/sapronlee/claude-plugins)，名字叫 `sapronlee`，市场里的所有插件共用，只需添加一次。`cc-doc-review@sapronlee` 的格式是「插件名@插件市场名」。

然后新开一个会话。不需要装 Go：第一次使用时，插件会从本仓库的 GitHub Releases 下载预编译好的文档服务（见[系统要求](#系统要求)）。

## 使用

界面语言跟随 Claude Code 的 `language` 设置：含「中文」「Chinese」「zh」时是中文，其余是英文。下面写的是中文界面里的名称。

1. **Claude 写文档。** 文件命中自动登记模式（见[配置](#配置)）时，插件自动登记；Claude 也可以用 `mcp__cc-doc-review__open_doc` 工具登记任意文件。登记只是让这份文档可以被回复，没有什么在等你表态。Claude 会在回话里附上文档的链接。
2. **打开文档。** 点 Claude 回话里的链接，或输入 `/cc-doc-review`（不带参数）在聊天里列出本会话的文档，最近更新的在上。每份一行：文档名（是文档页链接）、所在目录、更新时间，这份文档上有没发出去的回复时再显示「N 条回复待发送」。点链接在系统浏览器里打开文档页（桌面版会把本机链接送到系统浏览器）。桌面版里 Claude 有内置浏览器工具时，还会直接在对话旁边的浏览器面板打开文档页，不用切窗口。想自己登记一个文件，输入 `/cc-doc-review <文件>`：登记并在浏览器里打开。
3. **选中文字，写回复。** 在文档页选中一段文字，选区上方会弹出回复框（上方放不下时弹在下方）。直接打字，回车或点 ⊕ 图标加入，Shift+回车换行，Esc 或点框外取消。Mermaid 图、图片、画布和 iframe 里的内容不能回复。
4. **在输入框上方查看回复。** 加入的回复会显示在页面上：原文高亮，旁边有编号小圆点；点小圆点弹出你写的话，右上角的图标可以删掉这条。同时，Claude 输入框上方出现一个表格样式的回复列表：细线圆角外框，第一行是「↩ N 条回复」（只有一份文档时接上文档名），右边是〔清空〕〔发送〕；下面一条回复一行，行与行之间有横线，每行依次是橙色编号圆点（和页面上的一致）、灰色竖线加变暗的原文、你写的话，太长的截短。鼠标停在某行上，底色变浅，行尾出现 ×，点它删掉这一条。最多先列最新加入的 3 条，窗口矮、放不下时列得更少，不会把下面的用量带等挤走；列不全时标题行右边有〔展开其余 N 条〕。〔清空〕删除全部，要在 3 秒内点两次（第一次点击会变成〔确认清空〕）。编号在整个会话内连续，和页面上的小圆点一致。
5. **发送。** 在输入框里按回车（先是你写的话，再是回复），或点回复列表的〔发送〕（只把回复作为你的消息发出）。斜杠命令、插件或通知消息都不会带上回复。发出后回复列表收起，页面上的标记清掉；点〔发送〕时还会提示「已发给 Claude」。
6. **Claude 按编号答复。** 发出的消息在聊天记录里画成和回复列表一样的列表，你自己写的话放在下面。桌面版里按回车发出的消息，要等桌面版把这条消息同步过来（一般在 Claude 回话前后）才会画成列表；点〔发送〕的马上就是列表。Claude 在回话里按编号逐条说明处理结果，并按需修改文档。没有状态要更新，也不会有提醒。
7. **看改了哪里。** 文档文件变化时，页面自动刷新，改过的段落左侧画一道强调色竖线并加淡底色。顶栏显示「改了 N 处」，旁边的 ⌃ ⌄ 在改动之间跳转，✕ 清掉标注。刷新后会自动滚到第一处改动，但你正在写回复或 3 秒内刚滚动过时不滚。只标出页面打开期间发生的改动。

### Claude 收到的内容

回复会写进消息正文，格式如下：

```
[文档回复] 请按编号逐条答复。
笔记.md（docs/笔记.md）
<!-- reply 1 -->
> 文档里被引用的原文

你的回复

<!-- reply 2 -->
> 另一段原文

另一条回复
```

回复块以 `[文档回复] 请按编号逐条答复。` 开头（界面是英文时为 `[Doc reply] Please answer each by number.`），后面每份文档一行，写文档名和路径（在工作目录下时写相对路径），然后每条回复依次是 `<!-- reply N -->`、`> ` 开头的原文、一个空行和你写的话。聊天记录里插件把这条消息重画成回复列表，只改显示，Claude 收到的还是上面这些文字。如果你手动改过回复块、插件认不出，就按普通文字显示。

### 桌面版与命令行版

两边都有输入框上方的回复列表和聊天记录里的列表。打开文档都靠 Claude 回话里的链接，或 `/cc-doc-review`。

输入框上方这块位置由多个插件共用，按加载顺序一层套一层。本插件画完自己的回复列表后，会把内层插件（比如用量插件 [CC-Gauge](https://github.com/sapronlee/cc-gauge)）的内容接在下面；没有回复时什么都不画，把位置让给其他插件。

### 休眠模式

插件全局安装，但在会话里真正用到文档之前一直休眠：不往系统提示里加规则（工具说明仍在），也不轮询。休眠时仍保留 `open_doc` 工具、斜杠命令和写文件时的路径匹配。出现以下任一情况就唤醒，并保持到会话结束：Claude 调用 `open_doc`、你使用 `/cc-doc-review`、自动登记命中，或本会话登记过文档（会话开始时查一次；服务不在时读本机数据，本会话有文档就直接启动服务）。`/clear` 后回到休眠。

## 配置

有两种设置方式，修改后新开的会话生效：

- 在命令行版 Claude Code 里运行 `/plugin`，进入已安装的插件，选中 `cc-doc-review`，选「Configure options」。
- 直接编辑 `~/.claude/settings.json`，选项在 `pluginConfigs` 下，键是「插件名@插件市场名」。没写的项用默认值：

```json
{
  "pluginConfigs": {
    "cc-doc-review@sapronlee": {
      "options": {
        "includePatterns": "design/**/*.md,**/specs/**/*.md",
        "excludePatterns": "**/drafts/**",
        "autoRegister": true
      }
    }
  }
}
```

| 选项 | 默认值 | 含义 |
|---|---|---|
| `autoRegister` | `true` | Claude 写完命中模式的文档后自动登记，方便你直接回复。关闭后只能用 `/cc-doc-review <文件>`，或让 Claude 调用 `open_doc`。 |
| `includePatterns` | `**/*.{md,markdown,html,htm}` | 要登记的文档的 glob 模式，逗号分隔。 |
| `excludePatterns` | `**/.superpowers/**,**/node_modules/**,**/vendor/**,**/dist/**,**/.git/**,**/.claude/**,**/README*,**/CHANGELOG*,**/CLAUDE.md,**/AGENTS.md,**/LICENSE*,**/CONTRIBUTING*,**/SECURITY*,**/CODE_OF_CONDUCT*,**/.github/**,**/build/**,**/coverage/**` | 绝不登记的 glob 模式，逗号分隔。 |

模式语法：

- 模式匹配**相对会话工作目录**的路径，不区分大小写。
- `**` 匹配任意层目录，`*` 匹配名称中的任意字符，`?` 匹配单个字符，`{a,b}` 匹配其中之一。大括号里的逗号不会拆分模式。
- 单个模式最多 8 个 `*` / `**` 通配符（展开 `{a,b}` 后逐项计算），超过的模式会被忽略。
- 同时命中包含和排除的路径按**排除**处理（排除优先）。
- 包含模式留空什么都匹配不到，所以自动登记什么也不做。
- 以 `/` 开头的模式，以及以 `/` 结尾的目录式模式（如 `docs/`），什么都匹配不到；请改写成 `docs/**`。
- 只考虑主对话里用 Write 或 Edit 写的文件。工作目录之外的文件、子代理写的文件始终不自动登记。
- 例：只想登记 `design/` 下的 Markdown，把 `includePatterns` 改成 `design/**/*.md`。

自动登记失败只提示一次，之后一分钟内不再尝试。

## 工作方式

```
Claude 写文档 ──> 插件钩子 ──> 本地文档服务（127.0.0.1）──> 浏览器里的文档页
                                                              │ 你选中文字写回复
                                                              v
Claude 按编号答复 <── 随你的下一条消息发出 <── 输入框上方的回复列表
```

- `server/`：Go 写的小型服务（只用标准库），监听 `127.0.0.1` 的 4823～4830 端口，用令牌保护。它提供文档页，并把文档和回复保存在 `~/.claude/cc-doc-review/`。还没发出的回复在数据里是草稿，界面上叫待发送的回复。文档页打包进二进制，通过服务器推送（SSE）在文件或回复变化时自动刷新；Markdown 用 marked 渲染、DOMPurify 净化，代码和图表用 highlight.js 和 mermaid（见 `THIRD_PARTY_NOTICES.md`）。
- `hooks/` 和 `src/`：Claude Code 插件（hooks 模块），负责启动服务、登记文档。唤醒期间它每秒读一次 `/api/replies`，让输入框上方的回复列表保持最新；你发送时，它把回复写进你的消息，并在服务端把这些回复标为已发送。
- 提供给 Claude 的工具：`mcp__cc-doc-review__open_doc`。

## 从 0.2.0 升级

0.3.0 用「在文档上回复」取代了原来的评审流程：

- 评审状态和「通过」按钮没有了，页面上的〔发送给 Claude〕、评论栏、送达重试和提醒也一并去掉。不再有什么在等你表态。
- 旧的评论仍留在数据目录里，但不再显示。
- 0.2.0 里没发出去的草稿，会作为待发送的回复出现在输入框上方的回复列表里，发出或删掉都行。
- 工具 `review_open` 改名为 `open_doc`。如果你的权限规则里写了 `review_open`，请改成 `open_doc`。另外两个工具已删除，涉及它们的规则可以去掉。

## 安全说明

- 服务只监听 `127.0.0.1`，并只接受 Host 为 `127.0.0.1:<端口>` 或 `localhost:<端口>` 的请求。
- 文档页链接里带着访问令牌（参数 `t`），每次服务启动时重新生成。
- 打开 **HTML** 文档时，回复脚本注入在该页面里，页面自己的脚本也能读到这个令牌，进而调用服务接口；只打开你信任的 HTML。
- `/static/`（内置前端文件）和 `/api/health`（只返回名称和版本）不校验令牌。
- `/asset` 同样不校验令牌，提供 HTML 文档所在目录及其子目录下的资源，不提供以点开头的文件或目录（`.env`、`.git` 等）。文档 ID 由文件路径推算（绝对路径 SHA-1 的前 16 位十六进制），本机上的其他进程可以对已登记的 HTML 文档请求 `/asset`。
- 你的文档和回复不会上传到任何地方。文档页面里引用的远程图片、脚本仍会由你的浏览器去请求；每个新版本首次使用时会从 GitHub Releases 下载一次服务程序。

## 系统要求

- macOS 或 Linux（x86_64 或 arm64），不支持 Windows。
- 支持插件的 Claude Code。
- 第一次使用时，插件用 `curl` 从本仓库的 GitHub Releases 下载对应平台的预编译服务程序，按该版本的 `SHA256SUMS` 校验 SHA-256，保存为 `~/.claude/cc-doc-review/bin/cc-doc-review-server-<版本>`。下载失败而本机装有 Go 1.24 及以上时，退回本地编译 `server/`；两者都不行会给出带平台和原因的错误。
- `/plugin update` 之后，需要的新版本程序会按需下载，运行中的旧版服务会重启为新版。

## 开发

```
make build     # 编译 bin/cc-doc-review-server，版本号取自 .claude-plugin/plugin.json
make test      # Go 测试与 vet、前端测试、插件测试
make run       # 编译并运行服务
```

- `./bin/cc-doc-review-server -port <端口>` 只监听指定的单一端口，不在 4823～4830 中扫描。
- **开发模式：** 插件目录下有 `bin/cc-doc-review-server` 时，插件优先用它而不是下载的版本，版本变化也不自动重启。改了服务代码后，先结束旧进程（`kill $(jq .pid ~/.claude/cc-doc-review/server.json)`），再 `make build`，下次调用时就会启动新版本。想从工作副本运行插件，用 `claude --plugin-dir <路径>` 启动 Claude Code；桌面版等没法传参数的场景，改为设置环境变量 `CLAUDE_CODE_PLUGIN_DIRS` 指向该目录。
- 服务日志：`~/.claude/cc-doc-review/server.log`。
- **发版：** 修改 `.claude-plugin/plugin.json` 的 `version`，再推送同名标签 `v<版本>`。GitHub Actions 会检查标签是合法版本号且与 `plugin.json` 一致，运行 `go test` 和 `go vet`，编译四个平台的程序，连同 `SHA256SUMS` 上传到该标签的 Release；标签与 `plugin.json` 版本不一致会失败。[插件市场](https://github.com/sapronlee/claude-plugins)里本插件的条目不带版本号，所以只需改 `plugin.json`。`make release-local` 在本地演练产物，输出到 `dist/`。打标签前请先在本地运行 `make test`：CI 只跑 Go 测试，不跑前端和插件测试。

### 从旧版 `doc-review` 迁移

旧版插件名为 `doc-review`，数据在 `~/.claude/doc-review/`。新版服务首次启动时，会结束仍在运行的旧服务；新目录里没有 `docs/` 时，把旧目录的 `docs/`、`outbox/` 复制过来。旧目录保留不删。
